  Workflow — .github/workflows/backend-ci.yml

  New step: "Publish Laravel public directory" (runs last, after migrations). It
  rsyncs $DEPLOY_PATH/public/ → $PUBLIC_PATH/ on the host — a local rsync, so
  nothing is uploaded twice.

  It reads a new HOSTINGER_PUBLIC_PATH (secret or repo variable — secret wins).
  Unset, the step skips entirely, so it's opt-in and nothing about the current
  deployment changes until you set it. I added guards your snippet didn't have,
  because --delete in a web root is unforgiving:

  ┌────────────────────────────┬────────────────────────────────────────────┐
  │         Situation          │                 Behaviour                  │
  ├────────────────────────────┼────────────────────────────────────────────┤

  │  or moved doc root)        │                                            │
  ├────────────────────────────┼────────────────────────────────────────────┤
  │ target is / or $HOME       │ refuses                                    │
  ├────────────────────────────┼────────────────────────────────────────────┤
  │ the Laravel tree sits      │ refuses, with the mkdir laravel command to │

  │ current layout)            │                                            │

  │ laravel/public doesn't     │ fails with which one                       │
  │ exist                      │                                            │
  ├────────────────────────────┼────────────────────────────────────────────┤

  └────────────────────────────┴────────────────────────────────────────────┘

  Ordering is deliberate: it runs after the migrate step, which aborts when the
  host has no .env. So a misconfigured DEPLOY_PATH can never reach the delete,
  and storage:link has already created public/storage for the sync to carry
  across (verified — the absolute symlink still resolves from public_html).

  .htaccess is excluded as you specified, which left two ways to break the site,
  so both are handled: absent → Laravel's public/.htaccess is copied in;
  present but with no front-controller rewrite (an hPanel PHP-handler default) →
  Laravel's rules are appended, keeping the existing block, idempotently;
  present with the old RewriteRule ^(.*)$ public/$1 → the deploy fails loudly,
  because under the new layout that rewrite 404s the entire site.

  Other changes: optimize:clear now runs before
  config:cache/route:cache/view:cache, with a fallback to individual clears if
  the cache store is unreachable (optimize:clear runs cache:clear, which throws
  on a dead store). --generate-password is removed from
  admin:create-super-admin. The document-root .htaccess restore is skipped once
  HOSTINGER_PUBLIC_PATH is set, since laravel/ isn't served.
